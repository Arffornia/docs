# Provisioning

**Repo:** [Arffornia_Provisioning](https://github.com/Arffornia/Arffornia_Provisioning) ·
**Stack:** TypeScript, Docker, `@arffornia/nexus_mods`

Provisioning is the **modpack definition** and the tool that applies it.

```
config/
  server/    modList.json · storage/ (configs, KubeJS, …) · index.json
  proxy/     same layout, for Velocity
  launcher/  same layout, for players' game folders
```

- `modList.json` lists mods by source: CurseForge `projectId/fileId`, Modrinth `versionId`,
  GitHub release `owner/repo/tag/asset`.
- `storage/` holds files copied as-is; `index.json` (SHA-1 per file) is regenerated by a bot
  commit on every push to `main`.
- Secrets are never committed: files carry `${CFG_*}` placeholders that the server image
  fills from Kubernetes Secrets (sourced from Vault).

The **config-updater** image runs as an init container before each server and proxy pod. It
calls Nexus_Mods to download what is missing, replace what changed and remove what is no
longer listed.

!!! warning "`main` is production"
    Servers resync at every start (daily, through the off-hours schedule) and launchers at
    every launch. A merge to `main` changes what every player and server runs. Release
    channels are an open question.

See [Content delivery](../architecture/content-delivery.md) for the full flow.
