# Translations (EN/FR)

Everything a player sees exists in English and French ([ADR-0002](../decisions/0002-english-codebase-bilingual-players.md)).
English is the fallback language.

## UI text

| Repo | Where strings live | Guard in `make check` |
|---|---|---|
| Website | `lang/{en,fr}/<group>.php`, used as `__('group.key')`; JS strings rendered as JSON by Blade | key parity test, Blade bare-text lint, both-locale page tests |
| Launcher | `src/renderer/src/i18n/locales/{en,fr}.json` (vue-i18n) | `vue/no-bare-strings-in-template`, parity and used-key tests |
| Mod | `assets/arffornia/lang/{en_us,fr_fr}.json`, `Component.translatable(key, args...)` | `LangFilesTest` (parity, arguments, used keys, no wordy `Component.literal`, no `§`) |
| Provisioning (KubeJS) | `kubejs/assets/<ns>/lang/{en_us,fr_fr}.json`, `Text.translatable(key)` | `tests/i18n-data.test.ts` |

French glossary: milestone = *jalon*, stage = *palier*, target = *objectif*, rewards = *récompenses*,
Space Elevator = *ascenseur spatial*.

## Data and API text

Text that arrives as data (database rows, API responses, JSON or scripts shipped by Provisioning) follows
[ADR-0009](../decisions/0009-player-text-in-data-and-apis.md). In short:

**Pick the class first.**

| If the text is... | Then | Example |
|---|---|---|
| a fixed label known at build time | ship a **key**, translate it in the client | KubeJS tooltip `Text.translatable("tooltip.kubejs.stellaris.fuel_refinery")` |
| free-form content written by staff | store a **localized object** | `"badge": { "en": "⭐ Recommended", "fr": "⭐ Recommandé" }` |
| a Minecraft item | send the **item id**; the client shows the item's own name | `ItemLabels.of(unlock.itemId(), unlock.displayName())` in the mod |
| a name (player, team, mod, brand) | leave it alone | `"displayName": "Applied Energistics 2"` |
| an API status or error | use `__('api.<id>')` from `lang/{en,fr}/api.php` | `__('api.player.not_found')` |

**Locale on the API.** `?locale=en|fr` > `locale` cookie > `Accept-Language` > `en`; the response
carries `Content-Language`. Clients send the language the player chose: the launcher sends its UI
language, the mod sends the player's game language (`fr_fr` becomes `fr-FR`). Responses keep their
shape: a translated field is a plain string, already resolved.

**Fallback.** Requested locale, then English, then any non-empty value. A blank translation counts as
missing.

**Do not**

- put words in a JSON text field as a plain string (`"description": "Fast & fluid"`): use `{ "en", "fr" }`;
- put words in a KubeJS script, a `say`/`tellraw` reward command or a `§` colour code: use a lang key;
- store an item's English name and show it: show the item from its id;
- return `'message' => 'Some words'` from a controller or service: add a line to `lang/{en,fr}/api.php`.

**Single-language surfaces.** The server-list MOTD and Discord (bot status, channel messages) have no
player locale; they use one language each, set in their config (see ADR-0009, open decision 3).

**Database content** (news, shop items, milestones, stages, graphs) moves to JSON columns with
`spatie/laravel-translatable`, table by table: see
[Arffornia_Website#100](https://github.com/Arffornia/Arffornia_Website/issues/100).
